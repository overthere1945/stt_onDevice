# STT_OnDevice 사용설명서 (Phase 1)

<!-- change(add)-hyungchul-2026-10-11-04:46 (Task 31) -->

이 앱은 스마트폰 안에서 여러 음성인식(STT) 엔진과 VAD(음성 구간 검출) 조합으로 음원 파일을 전사합니다.
결과 폴더를 PC 로 가져와 기존 PC 평가기(`run_eval.py`)로 WER/CER 을 계산해 가장 좋은 조합을 찾는 것이 목적입니다.
앱은 전사만 합니다. 정확도(WER/CER)는 앱에서 계산하지 않습니다.

- 대상 기기: Android 12(API 31) 이상, arm64-v8a. 측정 목표 기기는 Galaxy S25 Ultra 입니다.
- 설계서: [`docs/superpowers/specs/2026-10-09-stt-ondevice-phase1-design.md`](superpowers/specs/2026-10-09-stt-ondevice-phase1-design.md)
- 테스트 보고서: [`docs/테스트보고서_phase1.md`](테스트보고서_phase1.md)

## 1. 준비물

| 항목 | 값 |

| Android Studio | AGP 9.4.1 / Gradle 9.6.0 을 여는 버전. JDK 17 |

| 휴대폰 | 개발자 옵션 → USB 디버깅 켜기. PC 와 USB 연결 후 "USB 디버깅 허용" |
| 저장 공간 | 앱 약 120 MB + 모델(작은 것 수십 MB ~ 큰 것 1.5 GB). 여러 모델을 넣으면 수 GB |

## 2. 소스 받기와 외부 의존성

```bash
git clone git@github.com:overthere1945/stt_onDevice.git STT_OnDevice
cd STT_OnDevice
git checkout phase1                 # Phase 1 작업 브랜치
git submodule update --init         # whisper.cpp(v1.9.5), libfvad 서브모듈
tools/fetch_native_deps.sh          # TEN VAD .so·헤더, sherpa-onnx 1.13.8 AAR 내려받기 + SHA-256 확인
```

- `fetch_native_deps.sh` 는 정해진 버전만 받습니다. 해시가 다르면 아무것도 덮어쓰지 않고 실패(exit 1)합니다.
  이미 받아 둔 파일의 해시가 맞으면 다시 받지 않습니다. 저장소 어디에서 실행해도 됩니다.
- 받는 파일(모두 git 에 넣지 않음):
  - `app/libs/sherpa-onnx-static-link-onnxruntime-1.13.8.aar`
  - `app/src/main/cpp/third_party/ten-vad/` (libten_vad.so, ten_vad.h, LICENSE)
- 모델·음원은 저장소에 넣지 않습니다(원격 저장소가 공개 저장소이기 때문).

## 3. Android Studio 로 열기·빌드·설치

1. Android Studio → **Open** → `STT_OnDevice` 폴더 선택 → Gradle sync 가 끝날 때까지 기다립니다.
2. 실행 구성 `app` 을 고르고 연결된 휴대폰을 선택한 뒤 ▶(Run) 을 누릅니다. 또는 터미널에서:

```bash
./gradlew :app:assembleDebug                     # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:installDebug                      # 연결된 기기에 설치(데이터 유지)
./gradlew :app:testDebugUnitTest                 # PC 단위 테스트(기기 불필요)
tools/check_16kb.sh app/build/outputs/apk/debug/app-debug.apk   # 모든 .so 가 16 KB 정렬인지 확인
```

- 앱을 한 번 실행해야 기기에 앱 폴더 `/sdcard/Android/data/com.cowork.stt_ondevice/files/` 가 생깁니다.
  아래 adb 스크립트들은 이 폴더가 있어야 동작합니다.
- 현재는 **debug APK 를 쓰세요.** release 빌드는 2026-10-11 실기기 확인에서 앱 시작 즉시 종료되는 문제가 있습니다(테스트 보고서 3.3).
- 처음 실행할 때 알림 권한을 허용하세요. 실행 진행 알림이 보입니다(거부해도 실행은 됩니다).
- 주의: `./gradlew :app:connectedDebugAndroidTest`(기기 계측 테스트)는 **끝나면 앱을 지웁니다.**
  앱 폴더 안의 모델·음원·결과가 모두 사라지므로, 결과를 먼저 PC 로 가져온 뒤 실행하세요.

## 4. 모델 설치

앱 아래쪽 탭 **모델** 화면에서 합니다. 카드마다 이름·크기·언어·라이선스·상업 이용 표시(상업 가능 / 조건부 / 미확인)와 상태가 보입니다.
상태: 미설치 → 다운로드 중 → 검증 중 → **설치됨** (또는 손상).
**"설치됨" 인 모델만 실행할 수 있습니다.**

### 4.1 앱에서 다운로드
- 카드의 **다운로드** → 진행률 표시 → 끝나면 SHA-256 검사 후 "설치됨".
- **취소** 후 다시 다운로드하면 받은 부분부터 이어받습니다.
- 다운로드는 앱이 켜져 있는 동안 진행됩니다. 앱을 완전히 종료하면 취소됩니다(탭 이동은 괜찮음).

### 4.2 PC 에서 adb 로 넣기 (`tools/adb/push_models.sh`)
PC 에 이미 받은 모델(예: `tools/hash_models.py` 캐시 `tools/models_cache/`)을 그대로 보냅니다.

```bash
# 사용법: tools/adb/push_models.sh <model_id> <로컬 폴더 또는 .tar.bz2/.zip 파일>
tools/adb/push_models.sh vosk-small-ko-0.22 tools/models_cache/vosk-small-ko-0.22/dl0/vosk-model-small-ko-0.22.zip
tools/adb/push_models.sh sherpa-zipformer-ko-2024-06-24 tools/models_cache/sherpa-zipformer-ko-2024-06-24/dl0/sherpa-onnx-zipformer-korean-2024-06-24.tar.bz2
tools/adb/push_models.sh whispercpp-tiny tools/models_cache/whispercpp-tiny/dl0        # ggml-tiny.bin 이 든 폴더
```

- 파일 여러 개짜리 모델(예: FSMN VAD 의 `model_quant.onnx`·`am.mvn`·`config.yaml`)은 세 파일을 한 폴더에 모아 그 폴더를 넘깁니다.
- 스크립트가 기기의 `files/import/<model_id>/` 에 넣고, 앱이 읽을 수 있게 권한을 정리합니다(adb push 만 하면 앱이 하위 폴더를 못 읽습니다).
- 그다음 앱 **모델** 탭 → 그 모델 카드의 **가져오기** → **가져오기 실행**. 압축 해제·SHA-256 검사 후 "설치됨" 이 되면 끝입니다.
- `import/<model_id>/` 가 비어 있지 않으면 스크립트가 멈춥니다(섞임 방지). 필요 없으면 안내된 `adb shell rm -rf …` 명령으로 직접 지우세요.
- 모델 id 는 `app/src/main/java/com/cowork/stt_ondevice/model/ModelCatalogData.kt` 의 `id = "…"` 값입니다.

### 4.3 SAF(파일 선택기)로 넣기
- 카드의 **가져오기** → **폴더 선택(SAF)** 또는 **파일 선택(SAF)** → 휴대폰 안의 모델 폴더나 압축 파일을 고릅니다.
- 앱이 임시 폴더로 복사한 뒤 같은 검증을 거쳐 설치합니다. 복사 중에는 "검증 중" 으로 보이며, 이 단계는 취소 버튼이 없습니다.

### 4.4 VAD 모델
VAD 프리셋도 해당 VAD 모델이 "설치됨" 이어야 실행됩니다.

| VAD 계열 | 필요한 모델 id | 비고 |
|---|---|---|
| SILERO | `vad-silero-v6.2.3` | |
| PYA* (pyannote) | `vad-pyannote-seg3.0` | |
| FSMN | `vad-fsmn-zh-cn-16k-onnx` | 파일 3개 |
| YAMNET | `vad-yamnet-tflite-v1` | |
| FIRERED | `vad-firered-7990aac` | PC 에서 `tools/export/` 로 변환한 ONNX 를 adb/SAF 로 넣음(다운로드 URL 없음) |
| MARBLENET | `vad-marblenet-v2.0` | 같음 |
| WEBRTC, TEN, NONE | 없음 | 앱에 내장 |

## 5. 입력 음원 넣기

입력 폴더 규칙은 PC Tool 과 같습니다: `input_sound/<언어>/<상대 폴더>/<음원>.wav`.
언어 폴더는 `kr`(한국어) 또는 `en`(영어)이고, 그 아래 상대 폴더 구조가 결과 폴더에 그대로 반영됩니다.
음원은 16 kHz mono PCM16 WAV 가 기준이며, 아니면 앱이 변환하고 변환 시간(`preprocess_sec`)을 기록합니다.

### 5.1 adb (`tools/adb/push_inputs.sh`)
```bash
tools/adb/push_inputs.sh ~/workspace/stt/input_sound     # 그 아래 kr/ en/ 을 통째로(바뀐 파일만) 보냄
```
- 일부 파일만 보내려면 같은 구조의 임시 폴더를 만들어 넘기세요(예: `tmp/kr/customer/01.wav`).
- 끝나면 앱 **실행** 탭 → 입력 파일 **새로고침**.

### 5.2 SAF
- **실행** 탭 → **음원 가져오기(SAF)** → 폴더 선택.
  - **권장: `input_sound` 폴더(안에 `kr/`·`en/` 이 있는 폴더) 하나를 한 번에 고르세요.** 언어를 자동으로 알아보고
    `input_sound/kr|en/<시나리오>/NN.wav` 구조 그대로 복사합니다(예: 휴대폰 `Documents/input_sound` → 54개).
  - 폴더 이름이 `kr`/`en` 인 폴더를 고르면 그 언어로 복사합니다.
  - 시나리오 폴더(예: `Customer_Service`)를 따로 고르면 "어느 언어 폴더로 가져올까요?" 에서 언어를 묻고
    `input_sound/<언어>/<고른 폴더 이름>/` 아래로 복사합니다.
- wav 만 복사하고, 같은 이름 파일은 덮어쓰지 않고 건너뜁니다.

### 5.3 마이크
- **마이크** 탭 → 언어(kr/en) → 녹음 → 정지. `input_sound/<lang>/mic/<yyyyMMdd_HHmmss>.wav` 로 저장됩니다.
- 같은 이름의 `.info.txt` 에 실제 샘플레이트·채널·변환 여부가 기록됩니다.
- **실행 설정으로** 를 누르면 방금 녹음한 파일이 선택된 채로 실행 탭이 열립니다.
- 실시간 부분 결과(streaming partial)는 Phase 1 범위가 아닙니다(녹음 후 전사).

## 6. 실행 설정

**실행** 탭에서 다음을 고르고 아래 **실행** 을 누릅니다.

1. **입력 언어**: 한국어(kr) / 영어(en).
2. **입력 파일**: 폴더 트리에서 체크.
3. **모델**: 설치된 ASR 모델을 체크. 체크한 순서(1번, 2번…)가 실행 순서입니다.
   모델이 지원하지 않는 언어(예: Zipformer KO × en 파일)는 실행하지 않고 manifest 에 `UNSUPPORTED` 로 남습니다.
4. **VAD 프리셋**: 계열별로 접혀 있습니다. 펼쳐서 체크하면 값과 출처가 보입니다.
5. **실행 옵션**: chunk 묶기 방식(MERGE 기본 / INDIVIDUAL), 모델별 최대 chunk 길이(초, 비우면 기본값), 스레드 수(기본 4).
6. 화면 아래 **예상 조합 수**(모델 × 프리셋 × 지원 언어 파일)를 확인하고 **실행**.

실행 순서는 모델 → VAD 프리셋 → 파일입니다. 같은 프리셋의 VAD 결과는 캐시해 모든 엔진이 같은 구간을 씁니다(공정 비교).

### 6.1 VAD 프리셋 요약 (26종)

| 계열 | 프리셋 | 요점 |
|---|---|---|
| NONE | NONE | VAD 없음. 엔진 최대 길이로 고정 분할(기준선) |
| Silero v6.2.3 | SILERO, SILERO_SAFE, SILERO_FW, SILERO_DEFAULT, SILERO_SHERPA, SILERO_QWEN3, SILERO_WS, SILERO_USER | `get_speech_timestamps` 포팅. 프로젝트 기준·faster-whisper·sherpa·Qwen3 툴킷 등 원본 기본값 |
| pyannote seg-3.0 | PYA3_DEFAULT, PYA2_DIHARD3, PYA2_AMI, PYA2_VOXCONVERSE | onset/offset 히스테리시스 + 최소 길이 |
| FSMN (FunASR) | FSMN_DEFAULT, FSMN_ASR30 | E2EVadModel 상태기계. ASR30 은 최대 구간 30 s |
| WebRTC (libfvad) | WEBRTC_LIB_DEFAULT, WEBRTC_PYEXAMPLE, WEBRTC_ANDROIDVAD | 라이브러리 기본 / py-webrtcvad 예제 링버퍼 / android-vad 설정 |
| TEN VAD | TEN_DEFAULT, TEN_SHERPA | 원시 flag 병합 / sherpa 설정 |
| FireRedVAD | FIRERED_OFFLINE, FIRERED_STREAM | 공식 후처리 포팅 |
| MarbleNet v2.0 | MARBLENET_NEMO | NeMo 후처리 |
| Yamnet | YAMNET_NORMAL, YAMNET_AGGRESSIVE, YAMNET_VERY_AGGRESSIVE | android-vad 임계값 매핑 |

자세한 값과 출처는 설계서 §7.3 과 앱 화면의 "출처"·"주의" 문구를 보세요.

## 7. 진행·취소·이어하기

- **진행** 탭: 현재 모델/VAD/파일, 전체 진행률, 경과 시간, 오류 수, **실행 취소**.
- 실행은 포그라운드 서비스에서 돌아가므로 화면을 꺼도, 다른 탭으로 가도 계속됩니다(알림에 진행률과 "취소" 표시).
- **취소**: "취소 요청됨 — 현재 처리 중인 조각이 끝나면 멈춥니다". sherpa 엔진은 조각 하나의 decode 가 끝나야 멈추므로
  큰 모델은 수 초 걸릴 수 있습니다.
- **이어하기**: **결과** 탭에서 끝나지 않은 run 의 **이어하기** 를 누르면 같은 run 폴더에 남은 항목만 실행합니다.
  같은 설정·같은 입력일 때만 이어할 수 있습니다. 이미 끝난 항목은 다시 하지 않습니다.
- 앱이 강제 종료되거나 기기가 꺼져 중간에 끊긴 항목은 이어하기 때 `CRASH_OR_KILLED` 오류로 기록되고 건너뜁니다(같은 크래시 반복 방지).

## 8. 결과 보기·내보내기

- **결과** 탭: run 목록 → run 을 펼치면 조합별 OK/ERROR 수 → 조합을 펼치면 파일별 행 → 행을 누르면 전사 미리보기.
- **내보내기(SAF)**: 폴더를 고르면 그 아래 `<run_id>/` 폴더로 통째로 복사합니다. 같은 이름이 있으면 `<run_id>_1` 처럼 붙입니다(덮어쓰지 않음).
  Android 11 이상은 Download 최상위 자체는 고를 수 없으니 그 아래 폴더를 하나 만들어 고르세요.
- 실행 중인 run 은 이어하기·내보내기 버튼이 숨겨집니다.

## 9. PC 로 가져오기와 PC 평가기 실행

```bash
tools/adb/pull_results.sh                                  # 가장 최근 run 을 ./device_results/<run_id>/ 로
tools/adb/pull_results.sh 20261011_103000 ~/stt_runs       # run_id·대상 폴더 지정
```

- 대상에 같은 run 폴더가 이미 있으면 덮어쓰지 않고 멈춥니다.
- 끝나지 않은 run 이면 경고합니다(일부 파일만 채점됨).
- 스크립트가 마지막에 언어별 평가기 명령을 출력합니다. 그대로 복사해 실행하세요. 형식:

```bash
(cd ~/workspace/python/asr_stt/stt_all_gui_2nd && \
 ~/workspace/python/venv_eval/bin/python run_eval.py \
   --ref ~/workspace/stt/answer_sheet/kr \
   --hyp ~/stt_runs/<run_id>/kr \
   --out ~/stt_runs/<run_id>_eval/kr --no-noformat)
```

- 평가기에서 모델 이름은 `<algo>_<model>_<VAD>`(예: `whispercpp_tiny_SILERO`) 로 나옵니다. 조합마다 하나씩 페어링됩니다.
- 영어 정답지의 화자 라벨(`Customer:` 등)이 제거되지 않으면 EN WER 이 실제보다 높게 나올 수 있습니다(평가기 쪽 문제, 앱 범위 밖).
- 평가 폴더(`<run_id>/kr`, `<run_id>/en`) 안에는 전사 txt 만 있습니다. `result.csv` 는 일부러 `_results/` 로 뺐습니다
  (평가기가 hyp 폴더 안의 CSV 를 별도 모델로 한 번 더 읽어 결과가 두 배가 되는 것을 막기 위해서).

## 10. 출력 파일 목록과 의미

기기: `/sdcard/Android/data/com.cowork.stt_ondevice/files/output_stt/<run_id>/` (run_id = `yyyyMMdd_HHmmss`)

| 경로 | 내용 |
|---|---|
| `<lang>/<algo>_<model>_<VAD>/<rel_dir>/<stem>.txt` | 전사 결과(PC faster-whisper 형식, UTF-8 BOM 없음). `[전체 텍스트]` 머리줄 + 한 줄 텍스트 + `[구간별] start, end, text` |
| `<lang>/<algo>_<model>_<VAD>/<rel_dir>/<stem>.ERROR.txt` | 그 파일이 실패한 경우: 단계(stage)·코드·메시지 |
| `_results/<lang>/<algo>_<model>_<VAD>/result.csv` | 조합별 결과 표. UTF-8 BOM, PC `STT_CSV_HEADER` 60열 그대로. `algo`=엔진, `model`=모델, `note` 에 `vad=…;chunk_mode=…;max_chunk=…` |
| `_summary/all_result_<run_id>.csv` | 모든 조합 result.csv 합본 + `vad` 열 |
| `details/<lang>/<combo>/<rel_dir>/<stem>.json` | chunk 별 원본 offset·텍스트·엔진 원문(raw), 시간(전처리·VAD·전사), 자원(PSS peak·CPU 시간·발열·배터리), 엔진 메타(버전·정밀도·스레드) |
| `vad_segments/<VAD>/<lang>/<rel_dir>/<stem>.json` | VAD 구간(초) — 같은 프리셋은 모든 엔진이 공유. 옆의 `<stem>.scores.f32` 는 프레임 점수(분할 지점 계산용) |
| `run_manifest.json` | 기기·앱 빌드, 모델 hash·라이선스, 프리셋 값, 입력 목록, `UNSUPPORTED` 목록, 시작·종료 시각, 이어하기 여부, 진행 중 항목(`inFlight`) |
| `_logs/run_<run_id>.log` | 실행 로그(항목 시작·끝, 오류) |

주요 값의 뜻:
- `status`: `OK` / `ERROR` / `NO_MATCH`(VAD 가 발화를 하나도 찾지 못함 → 텍스트 빈 값, PC 규칙과 같음).
- `transcribe_sec`: 엔진 전사 시간 합, `elapsed_sec`: 파일 전체 처리 시간, `rtf = transcribe_sec / audio_sec`.
- `rss_peak_mb`: 200 ms 간격으로 잰 PSS 최대값. 측정하지 못한 값은 빈 칸입니다(0 이나 추정치를 넣지 않음).

## 11. 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| `adb devices` 에 기기가 없음 / `unauthorized` | USB 디버깅을 켜고, 휴대폰 화면의 "USB 디버깅 허용" 을 누르세요. 케이블·USB 모드(파일 전송) 확인. Linux 는 udev 규칙이 필요할 수 있습니다 |
| 스크립트가 "기기가 2대" 라며 멈춤 | `ANDROID_SERIAL=<시리얼> tools/adb/push_inputs.sh …` 처럼 대상 기기를 지정 |
| adb push 한 음원·모델이 앱에 안 보임 | adb push 만 하면 하위 폴더가 `drwxrws--- shell` 이라 앱이 못 읽습니다. 반드시 `tools/adb/*.sh` 스크립트를 쓰세요(권한 정리 포함) |
| "앱 폴더가 없습니다" | 앱을 한 번 실행한 뒤 다시 시도 |
| 모델이 "설치됨" 이 아님(손상/검증 중) | 카드의 **검증** 으로 파일별 크기·SHA-256 문제를 확인 → **삭제** 후 다시 설치 |
| 실행 결과가 `MODEL_LOAD / MODEL_NOT_READY` | 실행 시점에 그 모델이 "설치됨" 상태가 아니었음(설치 중·손상). 다른 모델로 자동 대체하지 않습니다. 설치를 마친 뒤 다시 실행 |
| `CRASH_OR_KILLED` | 앞선 실행이 그 항목(또는 모델 로드·VAD 준비) 도중 강제 종료됐다는 뜻입니다. `run_manifest.json` 의 `inFlight` 에 끊긴 항목이 기록되고, 이어하기 때 그 항목을 오류로 남기고 건너뜁니다. 메모리 부족(큰 모델)이 흔한 원인 — 모델을 줄이거나 다른 앱을 닫고 다시 실행 |
| `OOM` | 큰 모델(medium f16, Omnilingual 1B 등) 메모리 부족. 모델을 하나씩 실행 |
| 16 KB 페이지 기기에서 설치 실패 | `tools/check_16kb.sh <apk>` 로 모든 `.so` 가 `Align 0x4000` 인지 확인. 이 저장소 빌드는 11/11 정렬됨 |
| 실행 시작 실패 "다른 실행이 진행 중" | 한 번에 하나만 실행됩니다. 진행 탭에서 끝나거나 취소될 때까지 기다리세요 |
| 진행 알림이 안 보임 | 알림 권한 거부 상태. 실행은 계속됩니다. 설정 → 앱 → 알림에서 허용 |
| 평가기에서 모델이 두 배로 나옴 | 예전 결과 폴더(평가 폴더 안에 result.csv 가 있던 버전)일 수 있습니다. 지금 버전은 `_results/` 로 분리돼 있습니다 |
| 오프라인(비행기 모드)에서 동작 확인 | 모델 설치 후에는 네트워크를 쓰지 않습니다. 확인 절차는 테스트 보고서 "오프라인 확인 절차" 를 보세요 |
