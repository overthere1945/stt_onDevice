이 앱은 스마트폰 안에서 여러 음성인식(STT) 엔진과 VAD(음성 구간 검출) 조합으로 음원 파일을 전사합니다.
결과 폴더를 PC 로 가져와 기존 PC 평가기(`run_eval.py`)로 WER/CER 을 계산해 가장 좋은 조합을 찾는 것이 목적입니다.
앱은 전사만 합니다. 정확도(WER/CER)는 앱에서 계산하지 않습니다.

- 대상 기기: Android 12(API 31) 이상, arm64-v8a. 측정 목표 기기는 Galaxy S25 Ultra 입니다.
- 설계서: [`docs/superpowers/specs/2026-10-09-stt-ondevice-phase1-design.md`](superpowers/specs/2026-10-09-stt-ondevice-phase1-design.md)

## 2. 소스 받기와 외부 의존성

```bash
git clone git@github.com:overthere1945/stt_onDevice.git STT_OnDevice
cd STT_OnDevice
git checkout phase1                 # Phase 1 작업 브랜치 (Phase 2 기능은 phase2 브랜치 — change(add)-hyungchul-2026-10-11-20:32)

```

- `fetch_native_deps.sh` 는 정해진 버전만 받습니다. 해시가 다르면 아무것도 덮어쓰지 않고 실패(exit 1)합니다.
  이미 받아 둔 파일의 해시가 맞으면 다시 받지 않습니다. 저장소 어디에서 실행해도 됩니다.
- 받는 파일(모두 git 에 넣지 않음):
  - `app/libs/sherpa-onnx-static-link-onnxruntime-1.13.8.aar`

- 모델·음원은 저장소에 넣지 않습니다(원격 저장소가 공개 저장소이기 때문).

## 3. Android Studio 로 열기·빌드·설치

1. Android Studio → **Open** → `STT_OnDevice` 폴더 선택 → Gradle sync 가 끝날 때까지 기다립니다.
2. 실행 구성 `app` 을 고르고 연결된 휴대폰을 선택한 뒤 ▶(Run) 을 누릅니다. 또는 터미널에서:

```bash
./gradlew :app:assembleDebug                     # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:installDebug                      # 연결된 기기에 설치(데이터 유지)
./gradlew :app:testDebugUnitTest                 # PC 단위 테스트(기기 불필요)
tools/check_16kb.sh app/build/outputs/apk/debug/app-debug.apk   # 모든 .so 가 16 KB 정렬인지 확인
```

- 앱을 한 번 실행해야 기기에 앱 폴더 `/sdcard/Android/data/com.cowork.stt_ondevice/files/` 가 생깁니다.
  아래 adb 스크립트들은 이 폴더가 있어야 동작합니다.
- release 빌드(`./gradlew :app:assembleRelease`)는 서명 설정이 없어 `app-release-unsigned.apk` 로 나옵니다. 기기에 넣으려면 직접 서명하세요(예: debug 키
  `apksigner sign --ks ~/.android/debug.keystore --ks-pass pass:android --ks-key-alias androiddebugkey --out app-release-signed.apk app/build/outputs/apk/release/app-release-unsigned.apk`).
  같은 키로 서명한 debug·release 는 `adb install -r` 로 서로 바꿔 설치해도 앱 데이터가 유지됩니다.
- 처음 실행할 때 알림 권한을 허용하세요. 실행 진행 알림이 보입니다(거부해도 실행은 됩니다).
- 주의: `./gradlew :app:connectedDebugAndroidTest`(기기 계측 테스트)는 **끝나면 앱을 지웁니다.**
  앱 폴더 안의 모델·음원·결과가 모두 사라지므로, 결과를 먼저 PC 로 가져온 뒤 실행하세요.

## 4. 모델 설치

앱 아래쪽 탭 **모델** 화면에서 합니다. 카드마다 이름·크기·언어·라이선스·상업 이용 표시(상업 가능 / 조건부 / 미확인)와 상태가 보입니다.
상태: 미설치 → 다운로드 중 → 검증 중 → **설치됨** (또는 손상).
**"설치됨" 인 모델만 실행할 수 있습니다.**

> <!-- change(add)-hyungchul-2026-10-11-20:32 --> 모델 화면 맨 위의 **시스템 엔진** 영역(ML Kit GenAI Basic, Android 온디바이스 인식기)은 모델 파일이 없고 언어별 상태로 표시됩니다. 12절을 보세요.

### 4.1 앱에서 다운로드
- 카드의 **다운로드** → 진행률 표시 → 끝나면 SHA-256 검사 후 "설치됨".
- **취소** 후 다시 다운로드하면 받은 부분부터 이어받습니다.
- 다운로드는 앱이 켜져 있는 동안 진행됩니다. 앱을 완전히 종료하면 취소됩니다(탭 이동은 괜찮음).

### 4.2 PC 에서 adb 로 넣기 (`tools/adb/push_models.sh`)
PC 에 이미 받은 모델(예: `tools/hash_models.py` 캐시 `tools/models_cache/`)을 그대로 보냅니다.

```bash
# 사용법: tools/adb/push_models.sh <model_id> <로컬 폴더 또는 .tar.bz2/.zip 파일>
tools/adb/push_models.sh vosk-small-ko-0.22 tools/models_cache/vosk-small-ko-0.22/dl0/vosk-model-small-ko-0.22.zip
tools/adb/push_models.sh sherpa-zipformer-ko-2024-06-24 tools/models_cache/sherpa-zipformer-ko-2024-06-24/dl0/sherpa-onnx-zipformer-korean-2024-06-24.tar.bz2
tools/adb/push_models.sh whispercpp-tiny tools/models_cache/whispercpp-tiny/dl0        # ggml-tiny.bin 이 든 폴더
```

- 파일 여러 개짜리 모델(예: FSMN VAD 의 `model_quant.onnx`·`am.mvn`·`config.yaml`)은 세 파일을 한 폴더에 모아 그 폴더를 넘깁니다.
- 스크립트가 기기의 `files/import/<model_id>/` 에 넣고, 앱이 읽을 수 있게 권한을 정리합니다(adb push 만 하면 앱이 하위 폴더를 못 읽습니다).
- 그다음 앱 **모델** 탭 → 그 모델 카드의 **가져오기** → **가져오기 실행**. 압축 해제·SHA-256 검사 후 "설치됨" 이 되면 끝입니다.
- `import/<model_id>/` 가 비어 있지 않으면 스크립트가 멈춥니다(섞임 방지). 필요 없으면 안내된 `adb shell rm -rf …` 명령으로 직접 지우세요.
- 모델 id 는 `app/src/main/java/com/cowork/stt_ondevice/model/ModelCatalogData.kt` 의 `id = "…"` 값입니다.

### 4.3 SAF(파일 선택기)로 넣기
- 카드의 **가져오기** → **폴더 선택(SAF)** 또는 **파일 선택(SAF)** → 휴대폰 안의 모델 폴더나 압축 파일을 고릅니다.
- 앱이 임시 폴더로 복사한 뒤 같은 검증을 거쳐 설치합니다. 복사 중에는 "검증 중" 으로 보이며, 이 단계는 취소 버튼이 없습니다.

## 5. 입력 음원 넣기

입력 폴더 규칙은 PC Tool 과 같습니다: `input_sound/<언어>/<상대 폴더>/<음원>.wav`.
언어 폴더는 `kr`(한국어) 또는 `en`(영어)이고, 그 아래 상대 폴더 구조가 결과 폴더에 그대로 반영됩니다.
음원은 16 kHz mono PCM16 WAV 가 기준이며, 아니면 앱이 변환하고 변환 시간(`preprocess_sec`)을 기록합니다.

### 5.1 adb (`tools/adb/push_inputs.sh`)
```bash
tools/adb/push_inputs.sh ~/workspace/stt/input_sound     # 그 아래 kr/ en/ 을 통째로(바뀐 파일만) 보냄
```
- 일부 파일만 보내려면 같은 구조의 임시 폴더를 만들어 넘기세요(예: `tmp/kr/customer/01.wav`).
- 끝나면 앱 **실행** 탭 → 입력 파일 **새로고침**.

### 5.2 SAF
- **실행** 탭 → **음원 가져오기(SAF)** → 폴더 선택.
  - **권장: `input_sound` 폴더(안에 `kr/`·`en/` 이 있는 폴더) 하나를 한 번에 고르세요.** 언어를 자동으로 알아보고
    `input_sound/kr|en/<시나리오>/NN.wav` 구조 그대로 복사합니다(예: 휴대폰 `Documents/input_sound` → 54개).
  - 폴더 이름이 `kr`/`en` 인 폴더를 고르면 그 언어로 복사합니다.
  - 시나리오 폴더(예: `Customer_Service`)를 따로 고르면 "어느 언어 폴더로 가져올까요?" 에서 언어를 묻고
    `input_sound/<언어>/<고른 폴더 이름>/` 아래로 복사합니다.
- wav 만 복사하고, 같은 이름 파일은 덮어쓰지 않고 건너뜁니다.

입력 목록 규칙(모든 방법 공통):
- 이름이 `.` 으로 시작하는 파일(`._01.wav` macOS 메타 파일, `.trashed-…` 휴지통 파일 등)은 음원으로 보지 않고 건너뜁니다.
- 같은 폴더에 이름이 대소문자만 다른 wav(예: `01.wav` 와 `01.WAV`)가 있으면 결과 파일 이름이 겹치므로 **둘 다 실행 목록에서 빼고**

### 5.3 마이크
- **마이크** 탭 → 언어(kr/en) → 녹음 → 정지. `input_sound/<lang>/mic/<yyyyMMdd_HHmmss>.wav` 로 저장됩니다.
- 같은 이름의 `.info.txt` 에 실제 샘플레이트·채널·변환 여부가 기록됩니다.
- **실행 설정으로** 를 누르면 방금 녹음한 파일이 선택된 채로 실행 탭이 열립니다.
- 실시간 부분 결과(streaming partial)는 Phase 1 범위가 아닙니다(녹음 후 전사).

## 6. 실행 설정

**실행** 탭에서 다음을 고르고 아래 **실행** 을 누릅니다.

1. **입력 언어**: 한국어(kr) / 영어(en).
2. **입력 파일**: 폴더 트리에서 체크.
3. **모델**: 설치된 ASR 모델을 체크. 체크한 순서(1번, 2번…)가 실행 순서입니다.
   모델이 지원하지 않는 언어(예: Zipformer KO × en 파일)는 실행하지 않고 manifest 에 `UNSUPPORTED` 로 남습니다.
   <!-- change(add)-hyungchul-2026-10-11-20:32 --> 목록 끝의 `mlkit`·`android-ondevice` 묶음이 시스템 엔진입니다. 공급 배속(1×·2×·4×)마다 따로 있으니 원하는 배속을 체크하세요(12절).
4. **VAD 프리셋**: 계열별로 접혀 있습니다. 펼쳐서 체크하면 값과 출처가 보입니다.
   <!-- change(add)-hyungchul-2026-10-11-20:32 --> 계열 목록 아래 **사용자 프리셋** 에서 기본 프리셋을 복사해 값을 바꾼 USER 프리셋을 만들고 고를 수 있습니다(13절).
5. **실행 옵션**: chunk 묶기 방식(MERGE 기본 / INDIVIDUAL), 모델별 최대 chunk 길이(초, 비우면 기본값), 스레드 수(기본 4).
6. 화면 아래 **예상 조합 수**(모델 × 프리셋 × 지원 언어 파일)를 확인하고 **실행**.

실행 순서는 모델 → VAD 프리셋 → 파일입니다. 같은 프리셋의 VAD 결과는 캐시해 모든 엔진이 같은 구간을 씁니다(공정 비교).

### 12.1 언어 상태 확인
**모델** 탭 맨 위 **시스템 엔진** 영역에 엔진마다 한국어·영어 상태가 보입니다.

| 상태 | 뜻 | 할 일 |
|---|---|---|
| 사용 가능 | 언어 팩이 설치돼 있어 바로 실행됩니다 | 없음 |
| 다운로드 필요 | 언어 팩이 없습니다(옆에 **다운로드** 버튼) | 12.2절 |
| 다운로드 중 | 앱이 요청한 다운로드를 추적하는 중(옆에 **취소** 버튼) | 끝날 때까지 기다림 |
| 사용 불가(사유) | 그 기기·버전에서 쓸 수 없음(예: Android 13 미만, 마이크 권한 없음) | 사유대로 조치 |

- 상태는 화면을 열 때와 **새로고침** 을 누를 때 다시 조회합니다. 실행 시작 직전에도 같은 방법으로 다시 확인합니다.
- **사용할 수 없는 언어는 실행 전에 빠집니다.** 다른 엔진·언어로 몰래 바꾸지 않고, `run_manifest.json` 의 `unsupported` 에 `<조합>|<언어>` 로,
  `unavailableReasons` 와 실행 로그(`_logs/run_<run_id>.log` 의 `LANG_UNAVAILABLE` 줄)에 사유로 남습니다. 예상 조합 수보다 실제 항목 수가 적은 이유가 이것입니다.
- 단, **상태 확인 자체가 실패한 경우**(상태 확인 시간 초과 15 초, 상태 확인 중 오류)는 서비스가 잠시 멈춘 것일 수 있어 미지원으로 기록하지 않습니다.

### 12.2 언어 다운로드(사용자 동의)
1. **모델** 탭 → 시스템 엔진 영역 → 그 언어 줄의 **다운로드**.
2. 휴대폰에 Google 서비스의 동의·다운로드 창이 뜹니다(예: ML Kit 영어 약 62 MB, Speech Services by Google 창). **내용을 직접 확인하고 직접 승인**하세요. 앱은 이 창을 대신 누르지 않습니다.
3. 끝나면 상태가 "사용 가능" 으로 바뀝니다. 바로 바뀌지 않으면 **새로고침**.

- **취소** 는 앱이 다운로드를 **추적하는 것만** 끝냅니다. 이미 Google 서비스가 시작한 실제 다운로드는 그 서비스 안에서 계속될 수 있습니다.

- Android 온디바이스 인식기의 언어 다운로드는 Android 14 이상에서만 앱이 요청할 수 있습니다(Android 13 에서는 다운로드 버튼이 없습니다).
- 시스템 엔진에는 삭제·가져오기·검증 버튼이 없습니다(언어 팩은 Google 서비스가 관리).

### 12.3 공급 배속(1× · 2× · 4×)
- 시스템 엔진은 음원 파일을 직접 읽지 못하고 **실시간 음성처럼** 받아야 합니다. 앱은 VAD 조각을 PCM16 으로 바꿔 100 ms(3,200 바이트) 단위로 공급하는데,
  배속이 1× 이면 실제 시간 그대로, 4× 이면 4배 빠르게 넣습니다. 그래서 1× 는 전사 시간 ≈ 음성 길이입니다.
- 배속은 **모델 목록에서** 고릅니다(`ML Kit GenAI Basic (공급 1×)` 등 배속마다 항목이 따로 있음). 결과 폴더 이름과 CSV `note` 의 `feed=xN` 에 배속이 남아
  같은 run 안에서 배속끼리 비교할 수 있습니다.
- 조각 최대 길이 기본 30 초. 덮어쓰기는 **0 초 초과 60 초 이하**만 됩니다(0 = 무제한 금지 — 61 초가 넘는 세션은 앞부분이 잘리는 것이 실측됨).
- 엔진마다 조각 하나에 **조각 길이 ÷ 배속 + 15 초** 안에 끝 신호가 없으면 멈춤으로 보고 클라이언트를 새로 만들어 1회 다시 시도합니다.
- 실행은 항상 진행 서비스(포그라운드) 안에서 합니다. 실험(S22 Ultra)에서는 포그라운드 서비스 안이면 화면을 꺼도 정상이었고, 진짜 백그라운드에서는 오류 없이 응답이 멈췄습니다.
  (앱 배치로 시스템 엔진을 화면 끈 채 돌리는 확인은 아직 미수행 — 테스트 보고서 10.5)
  다른 엔진과 같이 **실행 탭에서 시작한 배치만** 시스템 엔진을 씁니다.

### 12.4 마이크(RECORD_AUDIO) 권한이 필요한 이유
- Android 온디바이스 인식기는 Android API 규칙상 **마이크 권한이 있어야** 인식기를 쓸 수 있습니다. 앱은 실제 마이크로 녹음하지 않고 음원 조각을 파이프로 넣지만, 권한 검사는 똑같이 받습니다.
- 권한 요청은 **마이크** 탭에서 합니다(녹음 버튼을 누르면 권한 창이 뜸 → 허용). 다시 묻지 않으면 휴대폰 설정 → 애플리케이션 → STT_OnDevice → 권한 → 마이크 허용.
- 권한이 없으면 모델 화면에 "사용 불가(마이크(RECORD_AUDIO) 권한 없음 …)" 로 보이고, 실행 전 확인에서 그 엔진의 해당 언어가 빠져 manifest 에 사유가 남습니다.
  실행 도중에 권한이 사라지면 그 항목은 `PERMISSION_MISSING` 오류로 기록됩니다.
- ML Kit GenAI Basic 은 이 권한이 없어도 됩니다.

## 13. USER VAD 프리셋 — Phase 2

기본 프리셋 26종의 값을 바꾼 **나만의 프리셋** 을 만들어 실행할 수 있습니다.

### 13.1 만들기
1. **실행** 탭 → VAD 프리셋 계열 목록 아래 **사용자 프리셋** 소제목의 **복사해서 만들기**.
2. **복사할 기본 프리셋 선택** 에서 기준을 고릅니다(예: `SILERO — SILERO`).
3. 그 계열의 값 칸이 기준 값으로 채워져 나옵니다. 바꿀 값만 고칩니다(예: threshold `0.35`). 칸 아래에 허용 범위가 보이고, 범위를 벗어나면 빨간 글씨로 알립니다.
4. **프리셋 이름** 을 넣고 **저장** → 목록에 `USER_<이름>` 으로 생기고 바로 선택됩니다.

- 이름 규칙: 한글·영문·숫자·`-` 1~32자(앞뒤 공백은 지움). 한글 자모만(예: `ㅋ`)은 안 됩니다.
  기본 프리셋·이미 있는 USER 프리셋과 **대소문자만 다른 이름도 중복** 으로 거부됩니다(예: `silero`).
- **NONE 은 복사할 수 없습니다**(바꿀 값이 없음).
- **저장한 뒤에는 값을 고칠 수 없습니다.** 다른 값이 필요하면 새 이름으로 다시 복사하세요(이어하기 때 값이 같아야 하기 때문).
- 결과 폴더 이름: `<algo>_<model>_USER_<이름>`(한글 이름 그대로). 저장 파일은 앱 내부 저장소 `files/user_presets.json`(adb 로 보이는 앱 폴더가 아니라 앱 전용 영역 — 앱을 지우면 함께 지워짐).

### 13.2 지우기
- 목록의 **삭제** 를 누르면 **항상 확인 창** 이 뜹니다("USER 프리셋 … 를 지울까요? 지우면 되돌릴 수 없습니다.") — **지우기** 를 눌러야 지워집니다.
- 그 프리셋을 쓰는 **미완료 run** 이 있으면 확인 창에 그 runId 와 "지우면 그 실행은 이어할 수 없습니다" 경고가 나옵니다.
- 지운 프리셋을 쓰던 run 을 이어하려 하면 "삭제된 USER 프리셋입니다: USER_… — 이 실행은 이어할 수 없습니다" 로 거부됩니다(기본 프리셋으로 대체하지 않음).
